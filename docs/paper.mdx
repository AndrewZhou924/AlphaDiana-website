# Paper and published results

**AlphaDiana: A Measurement System for Agents in Verifiable Reasoning Tasks** was published on arXiv on 14 October 2026.

[Read the paper](https://arxiv.org/abs/2610.20675) · [PDF](https://arxiv.org/pdf/2610.20675) · [Code and latest README](https://github.com/AndrewZhou924/AlphaDiana-dev)

The results on this website follow **arXiv:2610.20675v1**: Figure 5 for macro scores, Section 4 and Appendix D for component interventions, and Appendices B.1, B.2, and C.5 for settings and resource accounting. They are published study results, not scores from the quick-start example or local recovery runs.

## What the study measures

AlphaDiana compares complete model-harness systems and links their answers to execution status, traces, and resource records. Macro analyses compare complete agents; the paper's micro interventions examine **tools, skills, and memory** under matched conditions. Tool removal also changes tool-related instructions, while memory experiments change both persistence and memory-use instructions. Interpret each intervention as its full configuration, rather than an isolated causal effect of one mechanism.

The answer-based evaluation pairs **Qwen3.5-27B**, **Gemma-4-31B-IT**, and **Kimi-K2.6** with **OpenClaw 2026.3.7**, **ZeroClaw v0.6.9**, and **OpenCode v1.3.2**. Direct is the single-response, no-tool reference. Interactive evaluations use Qwen and Gemma with benchmark-native references.

## Sampling and budgets

- **AIME 26:** all 30 problems, four attempts per problem, temperature 0.6. Avg@4 is mean correctness across 120 attempts. Pass@4 is the fraction of problems solved at least once.
- **Other macro benchmarks:** one attempt per problem (Avg@1).
- **Within a model-task comparison:** the same task list and decoding policy, with top-p 0.95 and a per-request output limit of 131,072 tokens.
- **Time limits:** a 9,300-second controller or request cap; OpenClaw also has a 9,000-second stream-total cap. ZeroClaw allows 100 tool iterations per run and 200 actions per hour.
- **Default harness conditions:** native prompts and tools, without added skill libraries or instructions to use memory. Native memory remains available.

The README quick start, checked on 25 October 2026, runs OpenCode on three AIME tasks with one sample per task and no task retries. It is an onboarding example, not the AIME protocol above; use the paper settings explicitly for a reproduction.

These limits do not equalize total computation: a harness can make several model calls. The paper's settings are an experimental protocol, not a claim about the defaults of every downloadable configuration.

## Findings and limits

Harness effects depend on the model and task. All three harnesses reduce Qwen's scores on all five answer-based benchmarks, while ZeroClaw improves Gemma on all five. Tool, skill, and memory effects depend on the task and configuration. Correctness must also accompany behavior and resource measurements: low token entropy can occur in wrong answers, and fewer tokens per attempt need not mean fewer tokens per correct answer.

### Memory is part of the published study

Figures 13–14 and Appendix D.4 evaluate Qwen3.5-27B on AIME 26 with OpenCode, OpenClaw, and ZeroClaw, keeping model weights fixed:

| Paper condition | Retained state |
| --- | --- |
| Cross-Rollout | Writable memory across four attempts on one problem; cleared before the next problem |
| Cross-Task | Memory across Tasks 1–30 in each of four separate sequential runs; no sharing between runs |
| Cross-Dataset | Memory collected on AIME 25 and frozen before AIME 26; no updates on the target tasks |

Raw interaction histories and workspace files reset between attempts. Default Harness clears memory between attempts and does not explicitly instruct memory use. Relative to that default, the three memory conditions in Figure 13 improve OpenCode and reduce OpenClaw and ZeroClaw accuracy; all nine remain below Direct's 89.2% Avg@4. This is not a general claim that memory helps or hurts every agent.

The comparison combines memory instructions with persistence. OpenCode includes prior solutions in prompts; OpenClaw and ZeroClaw retrieve summaries. Retrieval, prompt length, and control loops differ, so the study does not isolate the cause of the score differences. Cross-Rollout attempts can reuse earlier solutions and are dependent; Cross-Task running accuracy also changes with task difficulty. See [Evaluation Axes](/docs/concepts/evaluation-axes) for the distinction between paper conditions and runtime configuration keys.

### Resource and process measurements

Entropy is computed from recorded top-K next-token probabilities, renormalized over the observed candidates; it is not full-vocabulary entropy. Action shares pooled across steps can be dominated by a single long trajectory and are not the same as an average of per-trajectory shares (Section 3, Figure 7).

Appendix B.2 notes incomplete output-token capture for several model-benchmark-harness combinations, including Qwen/AIME 26 with OpenClaw and ZeroClaw. Token means use attempts with recorded counts; missing usage is not evidence of zero consumption. Report capture coverage when comparing resource use.

The macro resource plots use each system's available cohort, without a common task intersection. In contrast, Figures 15–16 compare common Gemma task sets (198 GPQA-Diamond and 587 HLE-Verifiable tasks). Output tokens per correct answer include tokens spent on unsuccessful attempts and exclude input tokens; this is an output-token measure, not a monetary API bill.

Wall-clock measurements include serving, tools, and scheduling. Serving configurations, concurrency, and load were not fully matched across all source runs. These are observed execution times, not isolated measurements of harness overhead. Appendix C.5 reports a separate matched-attempt analysis and time-cap sensitivity study.
